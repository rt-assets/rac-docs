RAC FAQ

Pre-purchase questions for the Fab listing. Copy what you need.

Before You Buy
Do I need to know C++ to use this?
No. Every class, property, function, and event is fully exposed to Blueprints. You can build a complete grapple hook, zipline, or cable network without writing a single line of C++. The plugin is written in C++ for performance, but designed for Blueprint users.
Which Unreal Engine versions are supported?
UE 5.4, 5.5, 5.6, 5.7, and 5.8. Each version is compiled and tested separately. UE 5.3 and below are not supported.
Is there a demo project I can try before buying?
Yes. A full playable demo level is included as a separate download. It showcases every major feature - cable networks, physics coupling, grapple swinging, ziplines, tethering, cutting, pinning, extend/retract, and more. You can use the demo level as a starting point for your own project.
What platforms does it support?
RAC is a pure C++ plugin with no platform-specific code and no third-party dependencies. It uses standard UE APIs (traces, components, spline meshes) and should work on any platform Unreal Engine supports. It has been developed and tested on Windows.
How is this different from UE's built-in Cable Component?
The built-in Cable Component is a basic visual-only rope with no collision, no interaction, no cutting, no LOD, and no gameplay features. RAC replaces it with a full physics simulation (world collision, wind, drift), 8 gameplay components (swing, climb, pull, tow, zipline, tether, interaction, pulley), cable networks, Niagara integration, a 4-tier LOD system, runtime cutting with regrow, and much more.
Features
Can I make a grapple hook / Spider-Man swing?
Yes. The Swing Component does exactly this. Aim at a surface, fire a rope, swing on a pendulum with pump input, and launch off with velocity. It includes rope fire/retract animations, auto-pull-in, camera avoidance, configurable launch boost, and visual rope with collision. Drop it on your character and bind two inputs.
Can I make ziplines?
Yes. Drop a Zipline Cable actor into your level, set two endpoints, done. Players ride along it with gravity influence, optional pendulum swing, and manual speed control. You can also make any regular cable rideable by toggling a single bool.
Can players grab, drag, pin, and cut cables at runtime?
Yes. The Cable Interaction Component handles all of this. It supports two detection modes (proximity overlap and aim/crosshair ray), grabbing and dragging with the player, pinning cables to the world or to actors, unpinning, cutting, and sweep-cutting. Every action fires Blueprint events.
Can cables wrap around objects?
Yes. The Wrapping Cable is a separate cable type that dynamically creates wrap anchor points around world geometry as it's pulled around corners, pillars, and obstacles. It maintains independent physics chains between anchors and supports all the same features (cutting, riding, tethering, Niagara, LOD).
Can I attach cables to moving actors / skeletal meshes / sockets?
Yes. Cable endpoints can attach to any actor, with optional socket and offset. They follow the target in real time. You can also re-attach endpoints at runtime, free them to dangle, or pin individual particles to actors.
Can cables pull physics objects?
Yes, two ways. The Tow Component connects two actors with a spring-coupled cable (vehicles, crates, anything with physics). The Pull Component lets a player aim at a physics object and reel it in with a grapple rope. Both include break force, tension events, and visual ropes.
Can I spawn cable networks / webs automatically?
Yes. Place Cable Point Components on actors, configure connection rules (radius, max connections, minimum angle, channels), and the system builds cable networks at BeginPlay using deterministic auto-connect. There's also a Cable Web utility that generates web patterns from a set of points. A Cable Parent system lets you configure cable defaults (material, thickness, LOD, collision) for an entire network from one place.
Can I use Niagara effects on cables?
Yes. RAC includes a custom Niagara Data Interface that exposes cable particle positions in real time. Build ribbon effects, sparks, glow trails, or anything else that follows the cable shape. A sample Niagara system is included. Works with both regular cables and wrapping cables.
Can cut cables regrow?
Yes. Cutting splits a cable into two pieces. The original cable can regrow to its initial length at a configurable speed, with optional delay. It can even seek back toward its original attachment point and reattach. Cut pieces can auto-destroy after a timer, and you can assign different materials to the cut ends.
Can cables extend and retract at runtime?
Yes. Manual extend/retract with configurable speed and min/max length. There's also auto-extend (cable grows when pulled taut) and auto-retract (cable shortens when slack), both with configurable tension thresholds. This works for winch mechanics, auto-adjusting tethers, and grapple rope reeling.
Performance
How many cables can I have in a scene?
It depends on your settings, but dozens to hundreds is realistic with LOD enabled. The 4-tier LOD system (Full, Medium, Low, Sleeping) scales solver work, collision traces, visual segments, and shadow casting by distance. Cables far from the camera cost nearly nothing. There's also a global cable budget that caps how many cables run at Full and Medium LOD simultaneously, and parallel multi-threaded solving.
Do idle gameplay components cost performance?
No. Swing, Pull, Climb, and Tow components disable their tick when not actively in use. A character with all four components sitting idle costs zero simulation time.
How does collision work? Is it expensive?
Collision uses per-particle sphere traces against the world. You control the cost with Max Traces Per Frame - the default (8) spreads traces across frames so not every particle is checked every tick. An adaptive priority system ensures fast-moving and colliding particles get traced first. For fast ropes (grapple, swing), there's a high-fidelity mode that traces every substep. Segment-to-segment traces catch tunneling through thin geometry. You choose the quality/cost tradeoff per cable.
Technical
Does it support multiplayer / replication?
Multiplayer and replication are not officially supported. Basic property replication is available, but it is not a supported multiplayer workflow. See the full documentation for existing behavior and limitations.
My chain link cables are blurry?
Enable Chain Motion Vectors (TSR/TAA) on your Cable actor or Tow component to reduce chain ghosting, or switch your project's Anti-Aliasing Method to FXAA or None to avoid temporal blur. See the full troubleshooting steps for motion blur and other causes.
Is RAC compatible with Nanite?
Partial compatibility. RAC can be used in projects with Nanite enabled. Unreal Engine 5.4 and later support Nanite spline meshes, but not every RAC visual mode, mesh, and material combination has been validated with Nanite. Keep Nanite disabled on a cable mesh if it shows rendering issues; Nanite can remain enabled on other supported scene meshes. Nanite does not accelerate RAC's cable physics. See Epic's Nanite documentation for engine support.
Do cables collide with each other (self-collision)?
No. Cables collide with the world (static and dynamic geometry) but pass through each other. This keeps collision cost manageable and is fine for most gameplay scenarios. Self-collision / rope-to-rope collision is not currently supported.
What physics solver does it use?
Verlet integration with distance constraints. Configurable solver iterations (more = stiffer), substeps, and damping. It's not XPBD - stiffness depends on iteration count - but it's stable, fast, and well-suited to gameplay ropes where feel matters more than physical accuracy.
Does it use Chaos / PhysX?
Neither. RAC runs its own independent Verlet solver. It doesn't depend on the engine's physics system for cable simulation. It does use the engine's trace system for collision and the engine's physics for driving attached rigidbodies (tow, pull), but the cable itself is self-contained.
Can I use it alongside other physics plugins?
Yes. RAC has no dependencies beyond Core, CoreUObject, and Engine. It won't conflict with other plugins. The only interaction point is if both systems try to drive the same physics body.
What's the difference between Cable Actor and Wrapping Cable?
Cable Actor is the standard cable - a Verlet chain between two endpoints with spline mesh visuals. Great for most use cases. Wrapping Cable is a separate actor that dynamically wraps around geometry by creating anchor points at contact. It's heavier but enables ropes that pull around corners, pillars, and obstacles realistically. Both support cutting, riding, tethering, Niagara, and LOD.
Can I use my own meshes and materials?
Yes. Every visual element is configurable - cable mesh, material (with UV flow tiling), end cap meshes, seal cap meshes, pin meshes, nozzle particles, rope meshes for swing/pull/tow/tether, and endpoint meshes. A set of default meshes and materials is included to get started.
Support & Updates
Is documentation included?
Yes. Full online documentation with a Quick Start guide, detailed pages for every component, and a complete API reference covering every property, function, and event. A demo project with working examples of every feature is also included.
Will it be updated for future engine versions?
Yes. RAC is actively maintained and will be updated for new Unreal Engine releases. Bug fixes and feature updates are ongoing.
Where do I get support if I have issues?
Documentation is the first stop. For bugs or questions, reach out through the support channels listed on the Fab product page. Bug reports with reproduction steps get prioritized.
